/spec let's spec the authentication forms on /login and /signup pages.
They need email and password fields, a `hide password` icon and a submit button (signup/login).
The forms should only log details to the console for now, when they are submitted.  We should be
able to easily switch between the two forms

---
Build an endpoint to validate the user phone.
if the user phone number exist and the user has completed onboarding,
it should throw an error; otherwise it should allow the user to continue the onboarding process.

---
create the following endpoint for business type
- GET business type
- Create business type
- Update business type
- Delete business type

The business type model should include:
- id
- business type
- business type description

A user can has just one business type, 
there should be a one to one relationship

------

create a database seed for the users, business type, kyc table.
Ensure that one of the user has completed profile to be true.

-------
create a get user endpoint to return all the user record
including the kyc and the business type

create a user onboarding endpoint to profile the user,
the data fields to collect are 
`firstName`, `lastName`, `email`, `homeAddress`,
`userType` (which can be a customer or a seller),
referral code (which is optional).
if the `userType` is a seller, the following field should be in the
request:
`businessName`, `businessLocation`, `businessType`
